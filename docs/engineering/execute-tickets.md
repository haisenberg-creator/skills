## What it does

`execute-tickets` is the autonomous orchestrator that chews through a batch of tickets generated by `to-tickets`. Instead of you manually opening new conversation sessions per ticket and running `/implement`, `execute-tickets` works the **frontier** of unblocked tickets and dispatches isolated sub-agents sequentially to implement, verify, and commit each ticket.

## When to reach for it

You invoke this by typing `/execute-tickets` once your tickets have been published (either as local markdown files under `.scratch/` or on an issue tracker like GitHub).

| The work is…                                                | Reach for                                   |
| ----------------------------------------------------------- | ------------------------------------------- |
| A batch of published tickets ready for autonomous execution | `/execute-tickets`                          |
| A single ticket you want to implement interactively         | `/implement #ticket`                        |
| A spec not yet split into tickets                           | `to-tickets` first, then `/execute-tickets` |
| Not written down anywhere yet                               | `grill-with-docs`                           |

## What one run does

1. Reads the tickets to determine the dependency graph.
2. Identifies the **frontier** (all tickets whose blockers are completed).
3. Spawns a sub-agent to implement the next ticket via `implement` (using TDD and committing).
4. Marks the ticket as Done upon successful completion.
5. Loops back to compute the next frontier until all tickets are done.

## Where it fits

`execute-tickets` bridges ticket planning with automated implementation:

```txt
grill-with-docs → to-spec → to-tickets → execute-tickets (loops sub-agents with implement)
```
